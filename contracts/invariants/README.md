# TON CCIP Invariants

> **Base invariants**: The chain-agnostic base set of invariants is maintained in
> [chainlink-ccip](https://github.com/smartcontractkit/chainlink-ccip/tree/main/chains/evm/contracts/invariants/).
> The files below contain TON-specific invariant categories, deviations, and
> implementation notes. AI tools should use both the base files and these files
> for complete CCIP coverage.

## Context

TON CCIP contracts are written in Tolk and live under `contracts/contracts/ccip`.
The contract package still uses the Blueprint-era project layout, while Tolk
1.4.1 generated TypeScript wrappers live under `contracts/wrappers/gen/ccip`.
Older handwritten TypeScript wrappers and helpers also exist under
`contracts/wrappers`.

Go bindings live under `pkg/ccip/bindings` and are handwritten. Because TON does
not currently have autogenerated Go bindings, the Go layer is a major risk area
for serialization drift, type mismatches, opcode mismatch, and ABI drift.

The Acton linter is used for Tolk linting, but it does not currently support
custom lint rules. The standalone `scripts/oplint` tool checks only that Tolk
struct opcodes match the CRC32 checksum of the struct name, except where a
`nolint:opcode` comment documents an intentional exception.
