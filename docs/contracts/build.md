# Building Contracts

We use Blueprint to compile our contracts. Refer to the [Blueprint build documentation](https://github.com/ton-org/blueprint#building-contracts). To build a contract, a file ending in `.compile.ts` must be placed under `wrappers` in the blueprint project's directory.

```bash
# Enter the specific #contracts dev shell
nix develop .#contracts

# Build the contracts module
pushd contracts
yarn
yarn build
```

## Nix build

You can also build a `contracts` Nix package:

```bash
nix build .#contracts --print-out-paths # labeled pkg
```

Build `contracts` Nix package without checking out the source code locally:

```bash
nix build 'git+ssh://git@github.com/smartcontractkit/chainlink-ton'#contracts --print-out-paths # labeled pkg
```

## Build system layout (Blueprint vs Acton)

The contracts build is currently **split across two toolchains**. Both produce compiled artifacts under `contracts/build/`, but they are driven by different manifests:

- **Blueprint** (`yarn build` → `blueprint build --all`): driven by `wrappers/*.compile.ts` files. Each `<name>.compile.ts` produces `build/<name>.compiled.json`. This is the path used by the Jest tests and by `yarn generate-pkg`.
- **Acton** (`Acton.toml`): a newer manifest that declares each contract's `display-name`, `src`, and `domain`. It is used by abigen tooling.

Because the two manifests are not yet unified, contract metadata lives in several places that must be kept in sync by hand.

### Naming contract

Three names must agree for a contract to be consumable end-to-end:

1. **Artifact name** — the `wrappers/<name>.compile.ts` filename, which determines `build/<name>.compiled.json`. Tests load code via `contractCode.ccip.local('<name>')`, which reads `build/<name>.compiled.json`. Pool contracts use dotted names, e.g. `ccip.pools.LockReleaseTokenPool.compile.ts` → `contractCode.ccip.local('ccip.pools.LockReleaseTokenPool')`.
2. **Package metadata FQN** — the key in `build/contracts-pkg.json`, generated by `contracts/scripts/generateContractsPkg.ts` from its hardcoded `CONTRACTS` list. The Go deployment code (`pkg/bindings`, `deployment/utils/compiled_contracts.go`) looks contracts up by this fully-qualified name, e.g. `link.chain.ton.ccip.pools.LockReleaseTokenPool`.
3. **On-chain type-and-version name** — the `CONTRACT_NAME` / `FACILITY_NAME` constant in the contract's `types.tolk`, returned by the `typeAndVersion` getter.

`Acton.toml`'s `display-name` should match the on-chain name (convention 3). When adding or renaming a contract, update **all** of: the `compile.ts` file, the `CONTRACTS` list in `generateContractsPkg.ts`, the Go constants in `pkg/bindings/index.go`, the Tolk `CONTRACT_NAME`/`FACILITY_NAME`, and `Acton.toml`.
