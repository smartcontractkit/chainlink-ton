# CCIP value flow per handler

How each CCIP-owned handler funds the next hop today, as a checklist for setting min values. The
measured costs are in [gas-report.md](./gas-report.md). Paths are under `contracts/contracts/ccip/`.

Modes: `m0` regular (fixed value, fees from the value), `m1` pay fees separately (fixed value, fees
from the contract balance), `m64` carry all remaining message value, `m128` carry all balance.
`R0` reserves the balance the contract had before the message so `m128` only sends the inbound value.

Rules the tuning phase applies:

- A handler that sends exactly one continuation message should use `m64`, or `R0` + `m128` when the
  action fees must come out of the carried value too (`m64` alone loses them from the balance).
- A handler that sends more than one message, or a message plus an event, uses fixed values for all
  but the last continuation, which goes out with `R0` + `m128`.
- Reserves are taken where control leaves CCIP (executors before a pool call, Router before
  `ccipReceive`) so finalization is funded when control comes back, instead of relying on what the
  pool or receiver forwards.
